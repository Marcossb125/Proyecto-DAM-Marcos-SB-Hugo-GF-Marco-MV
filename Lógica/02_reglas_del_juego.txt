═══════════════════════════════════════════════════════════════
REGLAS DEL JUEGO — Turnos SIMULTANEOS + Bots
═══════════════════════════════════════════════════════════════

Todos los jugadores ejecutan cada fase al mismo tiempo.
La fase avanza cuando TODOS tienen isReady = true.
La ronda avanza al terminar la fase MOVIMIENTO.
Los slots sin humano son controlados automaticamente por el backend.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
FLUJO GENERAL POR FASE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. El backend inicia la fase y notifica a todos los clientes.
2. Los bots ejecutan sus acciones automaticamente y marcan isReady=true.
3. Los humanos ejecutan sus acciones y pulsan "Listo" (isReady=true).
4. Cuando players.every(p => p.isReady === true):
     - El backend aplica la logica de fin de fase.
     - Resetea isReady=false para todos.
     - Avanza a la siguiente fase.
     - Emite GAME_STATE_UPDATE a todos.

ORDEN DE FASES (por ronda, todos simultaneos):
  RECAUDACION → CONSTRUCCION → RECLUTAMIENTO → MOVIMIENTO → [nueva ronda]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
FASE RECAUDACION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Al iniciar la fase, el backend aplica ingresos a TODOS los jugadores:
  Para cada player:
    propios = territories donde ownerId === player.id
    creditBonus   = 100 + (propios.length × 20)
    manpowerBonus =  50 + (propios.length ×  5)
    Si propios.some(t => t.isRefinery): creditBonus += 100
    player.credits  += creditBonus
    player.manpower += manpowerBonus

Los bots marcan isReady=true inmediatamente.
Los humanos pulsan CONTINUAR → isReady=true.
Cuando todos ready → avanza a CONSTRUCCION.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
FASE CONSTRUCCION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Cada jugador (humano o bot) puede construir/destruir en sus propios
territorios de forma independiente. No hay conflictos entre jugadores.

Evento BUILD({ playerId, territoryId, buildingType }):
  Validaciones:
    1. territory.ownerId === playerId
    2. territory.buildingType === null
    3. player.credits >= BUILDING_COSTS[buildingType]
    4. buildingType en {CUARTEL, FABRICA, TORRE, MURO}
  Resultado:
    territory.buildingType = buildingType
    player.credits -= BUILDING_COSTS[buildingType]

Evento DESTROY_BUILDING({ playerId, territoryId }):
  Validaciones:
    1. territory.ownerId === playerId
    2. territory.buildingType !== null
  Resultado:
    territory.buildingType = null

Bot: elige construccion segun heuristica simple (o pasa directamente).
Cuando todos ready → avanza a RECLUTAMIENTO.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
FASE RECLUTAMIENTO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Cada jugador recluta en su propia base suprema. Sin conflictos.

Evento RECRUIT({ playerId, territoryId, troopSize }):
  Validaciones:
    1. territory.ownerId === playerId
    2. territory.hasSupremeBase === true
    3. troopSize >= 1
    4. troopSize × 50 <= player.credits
    5. troopSize × 10 <= player.manpower
  Resultado:
    player.credits  -= troopSize × 50
    player.manpower -= troopSize × 10
    Si existe army del jugador en ese territorio:
      army.troopSize += troopSize  (refuerzo)
    Si no:
      Crear nuevo Army { ownerId:playerId, territoryId, troopSize,
                         hasActedThisTurn:false }
      territory.occupiedByArmyId = nuevo army.id

Cuando todos ready → avanza a MOVIMIENTO.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
FASE MOVIMIENTO — Encolado y resolucion simultanea
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Durante la fase, cada jugador encola sus movimientos.
El backend NO los ejecuta hasta que TODOS pulsen Listo.

Evento MOVE({ playerId, armyId, toTerritoryId }):
  Validaciones:
    1. army.ownerId === playerId
    2. army.hasActedThisTurn === false
    3. toTerritoryId en territory.adjacentIds del territorio origen
    4. El army no tiene ya un movimiento encolado esta fase
  Resultado:
    Se anade a pendingMoves[playerId]: { armyId, toTerritoryId }

Evento RETREAT({ playerId, armyId }):
  El jugador decide no mover ese ejercito.
  army.hasActedThisTurn = true  (se marca para no poder ser movido)

--- RESOLUCION AL TERMINAR LA FASE ---

Cuando todos los jugadores tienen isReady = true, el backend
resuelve todos los pendingMoves en el siguiente orden:

PASO 1 — Detectar conflictos
  Para cada territorio destino, agrupar todos los ejercitos
  que intentan moverse alli.

PASO 2 — Resolver conflictos (multiples ejercitos al mismo destino)
  Si dos o mas ejercitos de distintos jugadores apuntan al mismo territorio:
    Se ordenan por troopSize desc.
    El mayor ataca al siguiente en combate (ver formula batalla).
    El ganador continua; el perdedor es eliminado.
    Si quedan mas ejercitos, el ganador sigue combatiendo.
    (Se aplican las perdidas del 20% por cada combate ganado.)

  Si dos ejercitos intentan intercambiarse (A→B y B→A al mismo tiempo):
    Ambos combaten en territorio neutral (se resuelve como batalla
    en el territorio de menor id de los dos, o en el origen del atacante).
    Ganador queda en el territorio destino; perdedor es eliminado.

PASO 3 — Aplicar movimientos simples
  Los ejercitos sin conflicto se mueven directamente:
    fromTerritory.occupiedByArmyId = null
    toTerritory.occupiedByArmyId   = armyId
    toTerritory.ownerId            = army.ownerId
    army.territoryId               = toTerritoryId
    army.hasActedThisTurn          = true

PASO 4 — Resolver conquista de ciudades
  Si el destino es territorio enemigo con edificio pero sin ejercito
  (occupiedByArmyId === null tras los pasos anteriores):
    defenseStrength = 30
      + 30 si MURO, + 20 si TORRE, + 20 si hasSupremeBase  (max 95)
    successChance = clamp((troopSize×5) - (defenseStrength×0.5), 5, 95)
    roll = random(0,100)
    Si roll <= successChance:
      army.troopSize = max(1, floor(army.troopSize × 0.7))
      territorio conquistado (ownerId cambia)
    Si no:
      army eliminado, fromTerritory.occupiedByArmyId = null

FORMULA DE BATALLA (entre ejercitos):
  attackPower = attacker.troopSize × random(0.8, 1.2)
  defendPower = defender.troopSize  (fijo)
  Si attackPower > defendPower → gana atacante
    winner.troopSize = max(1, floor(winner.troopSize × 0.8))
    loser eliminado; territorio pasa al ganador
  Si no → gana defensor
    attacker eliminado

PASO 5 — Fin de fase MOVIMIENTO:
  armies.forEach(a => a.hasActedThisTurn = false)
  pendingMoves se vacia
  currentTurn++  → SNAPSHOT a BD
  currentPhase = 'RECAUDACION'
  players.forEach(p => p.isReady = false)

COMPORTAMIENTO DE LOS BOTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Un jugador con isBot=true es gestionado automaticamente por el backend.
El backend actua como "jugador" en su nombre al inicio de cada fase.

RECAUDACION: marca isReady=true de inmediato (la recaudacion es auto).

CONSTRUCCION: heuristica minima (ej. construir MURO si tiene creditos
suficientes y un territorio sin edificio), luego isReady=true.

RECLUTAMIENTO: reclutar el maximo posible de tropas en la base suprema,
luego isReady=true.

MOVIMIENTO: mover el ejercito con mas tropas hacia el territorio neutral
mas cercano (o atacar si hay ventaja numerica clara). Encola movimientos
y marca isReady=true.

Los bots actuan con un retardo artificial de 1-3 segundos para que
la partida no avance instantaneamente al cambiar de fase.

UNION DE JUGADORES HUMANOS A SLOTS BOT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Cuando un humano se une a una partida en curso:
  1. Se le asigna el slot con isBot=true disponible (o el que elija).
  2. player.isBot       = false
  3. player.isConnected = true
  4. Si el bot ya habia marcado isReady=true en la fase actual:
       player.isReady queda true (la fase no se reinicia).
  5. El cliente recibe el GAME_STATE_UPDATE completo para sincronizarse.
  6. El humano puede actuar normalmente en la siguiente fase.

Si el humano se desconecta durante la partida:
  player.isConnected = false
  player.isBot       = true
  El backend retoma el control de ese slot desde la siguiente fase.
